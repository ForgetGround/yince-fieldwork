# 访前／访后关联与跳转修复验收

## 查到的问题及修复

| 问题 | 修复后的行为 |
| --- | --- |
| 访后任务打开访前抽屉，且丢失产品 | 有来源纪要的任务直接打开原纪要；客户级历史任务进入该客户跟进范围 |
| 访前跳转后不保留客户／产品，返回时选择重置 | 父页面统一保存访前选择和访后筛选，双向跳转保留客户和产品 |
| 访前页面、详细作战单的问询与材料各用一套逻辑 | 共用 `visitPrompts`；两处保存相同口径的准备清单 |
| 访前详细内容混入最近沟通记录 | 访前保留企业信息、规则、问询、准备与授权渠道；沟通记录、纪要和任务集中在访后 |
| 历史纪要缺失关联快照时借用最新快照 | 严格解析原 `briefId`，找不到时只读展示原始记录并提示，不改挂新快照 |
| 保存沟通后关闭就没有继续归纳入口 | 访后增加沟通记录列表，恢复原渠道、结果、原文和快照继续处理 |
| 只要同快照有过一次沟通，就能用其他原文生成纪要 | 服务端检查沟通 ID、客户、快照、渠道、原文一致；新纪要保存 communicationId；重复请求返回同一纪要 |
| 逾期待办跳到全部未完成任务 | 跳转时清除客户产品筛选并启用“仅逾期” |
| 通知跳转沿用其他客户筛选 | 任务通知携带目标客户，清除旧产品筛选 |

## 验证结果

- 生产构建及 TypeScript 检查通过。
- 36 项单元测试通过，包含客户／产品／原快照关联、跨客户拒绝、来源任务及旧数据兼容。
- 独立 `yince_test` PostgreSQL 集成测试 11 项通过，覆盖权限、跨空间、规则快照、沟通、纪要、任务、审查；增加重复生成和原文／渠道不一致的拒绝断言。
- 可重复运行的集成测试调整为验证客户进度不倒退，兼容测试库此前已完成的历史流程。
- 浏览器在隔离测试库走通：KH-020＋税易贷 → 保存访前 → 微信记录 → 关闭重开 → 生成纪要 → 确认生成任务 → 任务打开原纪要。
- 比较访前页面与详细作战单的问询、材料，内容一致，访前不含“最近沟通记录”。
- 返回访前仍选中 KH-020＋税易贷；切换科企融后不会展示税易贷记录，未准备时不能新增沟通。
- 逾期待办入口显示全部客户／全部产品下的“仅逾期”任务。
- 手机 390 × 844 检查通过。

## 线上复核

- 已发布至静态与 API 的 `20260930-journey-fix` 独立版本，健康检查通过。
- 线上 KH-003／科企融从访前到访后再返回，客户和产品保持一致。
- 产品库税易贷的 KH-017 作战单入口直接进入访前页面，并正确选中 KH-017／税易贷。
- 线上浏览器未发现控制台错误；其他项目进程及共享 Nginx、AI 配置校验值前后一致。

## 发布

仅发布银策独立静态站与 API；不更改数据库结构、账户、共享代理及其他项目服务。新增 communicationId 存于现有 JSON 业务记录，旧纪要保留原快照，兼容按同客户／快照／渠道／原文查找旧关联。
