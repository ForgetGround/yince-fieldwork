## 当前边界

- AI 草稿需人工核实；不会自动写入业务、审批、发送通信或跳转任意外部 URL。
- 没有流式输出；15 秒 provider 超时会明确提示重试。
- 客户摘要最多 15 位，用户明确提及的有权客户优先。详细原始记录、联系方式和坐标不作为模型上下文。
- 配额每用户每分钟 8 次、每空间每天 200 次；适配服务并发 2。

## 回答格式修复：20260930-chat-format

用户反馈反复出现“回答格式异常”。原实现对模型正文直接 `JSON.parse`，任一解析错误都丢弃整段回答；历史助手消息又只传回正文，未保持结构化输出约定。原始失败回答未保存，无法追溯每次报错的具体字符；针对这些确定存在的脆弱处理补上回归覆盖。

修复包括：完整 JSON 围栏兼容、可选字段默认值、逐卡片校验、完整普通文字的显式展示提示、多轮历史保持 JSON、格式错误自动重试一次。重试共用原 15 秒截止时间，不修改业务 API 网络隔离、权限与导航白名单，不把截断或破损 JSON 作为正常文字展示。

验证：

- 33 项单元测试通过；新增用例覆盖缺失字段、坏卡片、围栏、纯文字、连续格式错误、截断、重试次数／共同截止时间、上游限流不重试、导航过滤与 JSON 历史。
- 6 项 API 集成测试（包含父测试）通过，新增校验多轮请求中的助手历史仍是合法 JSON。
- Next.js 静态构建和 TypeScript 检查通过。
- 新版真实 Flash 连续四轮测试通过，包含引号话术、方案和简洁追问；另经线上完整 API 连续三轮，均成功，耗时约 1.2–1.9 秒，六条历史消息持久化成功。
- 前端、API 和 AI 服务已切换至 `20260930-chat-format`。没有数据库迁移；旧发布目录保留供回滚。
- 其他三个项目的 PID 和共享配置摘要均与发布前一致。
